# Отчёт: MCP-сервер `printing-kb-mcp`

Сервер даёт агенту два инструмента: базу знаний по FDM-печати (`docs/`) и навигацию по собственному исходному коду. Реализация на Node.js, `@modelcontextprotocol/sdk` + `zod`.

## 1. Как IDE/агент подключается к MCP-серверу

### Конфигурация

Сервер объявлен в [.mcp.json](.mcp.json) в корне проекта:

```json
{
  "mcpServers": {
    "printing-kb": {
      "command": "node",
      "args": ["src/index.js"]
    }
  }
}
```

Claude Code (CLI и расширение VS Code) читает этот файл при открытии проекта, спрашивает разрешение на запуск проектного сервера и сам стартует его как дочерний процесс. Отдельно запускать сервер не нужно. Имя `printing-kb` становится префиксом инструментов у агента: `mcp__printing-kb__docs_context`, `mcp__printing-kb__project_helper`.

### Транспорт: stdio

Сервер общается по stdio: клиент пишет JSON-RPC сообщения в stdin процесса и читает ответы из stdout ([src/index.js:18](src/index.js#L18)):

```js
await server.connect(new StdioServerTransport());
```

Поскольку stdout занят протоколом, все логи идут в stderr и в файл `logs/mcp-server.log` ([src/core/logger.js](src/core/logger.js)). Любой `console.log` в stdout сломал бы протокол.

### Жизненный цикл сессии

1. **Запуск.** Клиент выполняет `node src/index.js`. Вызывается `createServer()` ([src/server.js:26](src/server.js#L26)), создаётся `Server` с объявленной возможностью `tools` ([src/server.js:34](src/server.js#L34)).
2. **`initialize`.** Клиент и сервер обмениваются версией протокола и возможностями. Сервер сообщает своё имя и версию (`SERVER_INFO` из [src/config.js](src/config.js)) и то, что умеет отдавать инструменты.
3. **`tools/list`.** Клиент запрашивает список инструментов. Обработчик ([src/server.js:36-45](src/server.js#L36-L45)) возвращает для каждого `name`, `title`, `description`, `inputSchema`, `outputSchema`, `annotations`. Эти описания попадают в контекст модели, по ним она решает, какой инструмент вызвать.
4. **`tools/call`.** Модель вызывает инструмент с аргументами. Обработчик ([src/server.js:47-50](src/server.js#L47-L50)) передаёт вызов в `runTool`.
5. **Завершение.** При закрытии сессии клиент гасит процесс. На `SIGINT`/`SIGTERM` сервер закрывает соединение и лог ([src/index.js:8-15](src/index.js#L8-L15)).

```
IDE / агент                         printing-kb (node src/index.js)
    │── spawn процесса ────────────────────▶│
    │── initialize ───────────────────────▶ │
    │◀────────────── serverInfo, capabilities│
    │── tools/list ───────────────────────▶ │
    │◀──────────────── 2 инструмента + схемы │
    │── tools/call docs_context {...} ────▶ │  валидация → handler → конверт
    │◀──────────────────── CallToolResult    │
```

### Отладка без IDE

```
npm run inspect   # npx @modelcontextprotocol/inspector node src/index.js
```

MCP Inspector подключается тем же способом (stdio) и позволяет вызывать инструменты вручную.

## 2. Что считается «tool» в этом сервере

### Определение

Tool — это **одна именованная операция, которую модель может вызвать сама**, с формально описанным входом и предсказуемым выходом. В коде это простой объект с пятью полями (пример: [src/tools/docsContext.js:161-172](src/tools/docsContext.js#L161-L172)):

| Поле | Назначение |
|---|---|
| `name` | уникальный идентификатор (`docs_context`), по нему приходит `tools/call` |
| `title`, `description` | текст для модели: что делает инструмент и когда его вызывать. Это фактически часть промпта |
| `inputSchema` | Zod-схема аргументов. Для `tools/list` она переводится в JSON Schema ([src/server.js:12-15](src/server.js#L12-L15)) |
| `annotations` | подсказки клиенту: `readOnlyHint: true` (ничего не меняет), `openWorldHint: false` (не ходит во внешний мир) |
| `handler` | функция `(args, ctx) => data`, выполняющая работу |

Инструменты регистрируются одним массивом ([src/server.js:27](src/server.js#L27)). Чтобы добавить новый, достаточно создать такой объект и добавить его туда.

### Инструменты сервера

| Tool | Что делает | Действия (`action`) |
|---|---|---|
| `docs_context` | Достаёт контекст из базы знаний `docs/`: филаменты, принтеры, гайды | `list`, `search`, `read` (документ или секция) |
| `project_helper` | Навигация по коду самого сервера, только внутри корня проекта; `node_modules`, `.git`, `logs`, `docs`, `.claude` и секреты скрыты | `overview`, `tree`, `read_file`, `search_code`, `list_tools` |

Внутри одного инструмента операции различаются параметром `action`. Мы сознательно держим два крупных инструмента вместо восьми мелких: модели проще выбрать нужный, а описание в контексте короче.

### Что делает каждый вызов (общий конвейер)

Каждый вызов проходит через `runTool` ([src/server.js:55-97](src/server.js#L55-L97)):

1. поиск инструмента по имени. Если имя неизвестно, возвращается `UNKNOWN_TOOL`;
2. валидация аргументов Zod-схемой. При ошибке возвращается `VALIDATION_ERROR` со списком проблем;
3. вызов `handler`. Ожидаемые ошибки (`NOT_FOUND`, `ACCESS_DENIED`, …) приходят как `ToolError`, остальные как `INTERNAL_ERROR`;
4. упаковка результата в единый конверт и самопроверка конверта по схеме;
5. запись вызова в лог: имя, вход, выход, статус, длительность.

Поэтому используется низкоуровневый `Server`, а не `McpServer.registerTool`: так ошибки валидации и неизвестные инструменты тоже проходят через общий формат ответа и логгер.

### Формат ответа

Любой инструмент возвращает один и тот же конверт ([src/core/response.js](src/core/response.js)):

```json
{
  "schemaVersion": "1.0",
  "tool": "docs_context",
  "requestId": "uuid",
  "status": "success | error",
  "data":  { ... } | null,
  "error": { "code": "...", "message": "...", "details": ... } | null,
  "meta":  { "timestamp": "...", "durationMs": 3 }
}
```

Клиент получает его дважды: как JSON-текст в `content` (для моделей, которые читают только текст) и как `structuredContent`, соответствующий объявленной `outputSchema`. При ошибке выставляется `isError: true`.

### Чем tool не является

- **Не ресурс и не промпт.** Сервер объявляет только возможность `tools`. Документы из `docs/` не публикуются как MCP-resources, модель получает их только через вызов `docs_context`.
- **Не функция с побочными эффектами.** Оба инструмента только читают данные, файлы проекта они не меняют.
